# ChurchStudio 회원·입금·라이선스 운영 안내

## 현재 운영 흐름

1. 회원은 ChurchStudio 홈페이지에서 가입하여 로그인합니다.
2. 회원이 /payment 에서 교회명, 담당자, 연락처(선택), 입금자명, 신고 입금액, 신고 날짜를 등록합니다.
3. 서버가 주문번호 CSO-YYYYMMDD-XXXXXXXXXX 를 부여합니다. **신청서만으로 결제가 입증되지 않습니다.**
4. 관리자는 /admin/payments 에서 주문, 회원정보, 신고 입금액을 확인합니다.
5. 실제 농협 계좌의 은행 거래내역(인터넷뱅킹 또는 은행 앱)을 직접 열어 입금자, 입금액, 날짜/시간, 거래 식별번호를 대조합니다.
6. 관리자 화면에 은행명, 거래 식별번호, 입금자명, 실입금액, 은행 입금시각을 입력합니다. 구매자에게 안내한 금액과 일치하는지도 별도로 확인합니다.
7. 관리자는 두 확인란을 선택한 뒤 '입금 승인 · 영구 키 발급'을 누릅니다.
8. 서버가 같은 은행 거래번호 중복사용과 동일 회원에게 중복된 활성 라이선스 발급을 방지합니다. 승인과 거래증빙, 라이선스, 이력은 하나의 DB 트랜잭션에서 처리됩니다.
9. 회원은 /license 에서 로그인 비밀번호를 재확인해야 자신의 라이선스 키를 볼 수 있습니다.

## 관리자가 확인할 정보

- 회원: 이메일, 회원 고유번호, 가입일, 교회명, 담당자, 등록 연락처
- 구매 신청: 주문번호, 상품, **회원 신고 금액**, 신청일, 상태
- 은행 입금 증빙: 은행명, 고유 거래번호, **은행에서 확인한 실제 금액**, 입금자, 거래 시각, 확인 관리자와 시각
- 라이선스: 발급번호, 상태, 발급일, 만료 여부, 등록 기기와 최대 사용 대수(2대)
- 변경 이력: 입금 신청, 승인, 키 발급, 반려, 라이선스 차단/재활성화

## 주의 사항

- 은행 계좌 연결/은행 API/PG 연동은 아직 없습니다. 화면의 승인 표시는 은행 데이터의 자동 검증이 아닙니다.
- 거래 식별번호가 없는 이체내역은 은행의 확인 가능한 고유 참조정보가 필요합니다. 임의 숫자를 만들거나 거래번호를 재사용하지 마세요.
- 구매 정가가 설정되지 않았습니다. 반드시 **실제 안내한 판매/후원 금액**을 독립적으로 확인한 뒤 승인해야 합니다.
- 실수 또는 오입금은 승인하지 않고 정확한 반려 사유를 기록하세요.
- 키 발급은 사용 기간이 무기한인 라이선스이며, 최대 2대 장치 제한이 DB에 적용됩니다.
- **Windows EXE의 14일 체험 만료 강제는 별도 소스 수정과 실제 장치 시험이 필요합니다.** 현재 홈페이지 DB 설정만으로 설치본이 14일 후 종료되는 것은 아닙니다.
- 라이선스 차단은 DB상 발급 상태를 변경합니다. 이미 설치된 EXE가 차단 상태를 검사하는지 확인해야 합니다.
- 환불 송금은 이 홈페이지에서 실행할 수 없습니다. 은행에서 실제 환불을 별도로 수행하고 증빙을 확인한 뒤 라이선스 차단 등 후속 조치를 기록하세요. 금액별 환불 장부와 세금계산서 자동처리는 아직 지원하지 않습니다.
- 회원 연락처와 은행 증빙은 회원에게 공개하지 않습니다. 홈페이지 공개 영역 또는 GitHub 코드에 올리지 마세요.
- 서비스 운영 계정의 접근권한을 최소화하고, 금융 증빙 및 연락처의 보존기간·삭제 기준을 별도로 수립하세요.

- 회원 입금 신청: https://churchstudio-kr.vercel.app/payment
- 회원 라이선스 확인: https://churchstudio-kr.vercel.app/license

## 자료 보호

- `bank_transfer_requests`, `member_contacts`, `bank_deposit_evidence`, `commerce_audit_events` 는 일반 회원과 익명 사용자에게 직접 SELECT 권한을 부여하지 않습니다.
- 서버의 JWT 인증과 관리자 role 검사를 통과한 요청에만 운영 목록이 반환됩니다.
- 은행 승인 기록과 감사 이벤트는 일반 서버 서비스 역할도 수정/삭제할 수 없게 설정했습니다.
- 관리자의 전체 키 조회는 비밀번호 재확인이 필요합니다.
